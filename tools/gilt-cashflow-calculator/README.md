# Gilt Cashflow & Tax Calculator

A static, browser-only tool that answers: "what are the cashflows and
timing if I invest £x tomorrow, excluding fees, in a given UK gilt and
hold it to maturity?" — and how much of any gain is tax-free capital vs
taxable coupon income.

**This is an illustrative estimator, not investment or tax advice.** Prices
are delayed (LSE, refreshed once daily) and exclude the bid/offer spread
and any broker/platform fees. Always confirm the actual price with your
broker before dealing.

## Files

| File | Purpose |
|---|---|
| `calc.js` | Pure calculation engine — no DOM, no I/O, fully unit-testable |
| `calc.test.js` | Unit tests, run with `node --test calc.test.js` |
| `index.html` | UI: gilt picker, amount/settlement inputs, results, cashflow table |

`calc.js` is a plain UMD-style script: loaded via a `<script src>` tag in
the browser (attaching to `window.GiltCalc`) and also `require()`-able
directly from Node for the test suite — same file, no build step either
way. This matches the pattern used by `../salary-dividend-optimiser/`.

## Where the data comes from

`index.html` fetches `../../data/gilts.json` — a static file committed to
this repo, **not** generated by this tool. It's published daily by a
separate project, [giltfetcher](https://github.com/jobbl-les/giltfetcher),
running on a cron/systemd timer elsewhere: DMO's own gilts-in-issue report
is behind bot protection that blocks a static page's client-side fetch, and
the London Stock Exchange's price API (which has everything needed —
ISIN, name, maturity date, price) works server-side but is CORS-locked to
LSE's own origin, so a browser on this site can't call it directly either.
See that repo's README for exactly how the list, coupon dates, and
ex-dividend dates are derived and validated against DMO's authoritative
data.

If `data/gilts.json` is ever missing or stale, this tool still renders —
it just shows a "couldn't load" message rather than a stale/wrong number,
per the `.catch()` in `index.html`.

## The model

Only **conventional (fixed-coupon) gilts** are covered — index-linked
gilts are filtered out of the picker entirely. Their future coupon and
redemption amounts are scaled by RPI inflation between now and each
payment date, which is unknowable in advance; projecting them would be
fake precision, not a genuine illustration.

Given a gilt, a cash amount, and a settlement date (defaults to tomorrow):

1. **Nominal purchased** = `investment × 100 / price` (price is quoted per
   £100 nominal).
2. **Coupons**: UK gilts pay semi-annually. A coupon is included only if
   the settlement date is strictly before that coupon's own ex-dividend
   date (`data/gilts.json` publishes one per coupon) — otherwise it's
   already gone to whoever held the gilt at the ex-dividend date, and the
   buyer's first coupon is the following one. Each coupon paid =
   `nominal × couponPercent / 100 / 2` (half the annual rate, since it's
   paid twice a year).
3. **Redemption**: conventional gilts redeem at par — 100% of nominal — on
   the redemption date, regardless of the price paid.
4. **Tax split**:
   - *Capital element* = `redemption amount − amount invested`. This is
     **exempt from Capital Gains Tax** under
     [TCGA 1992 s.115](https://www.gov.uk/guidance/gilt-edged-securities-exempt-from-capital-gains-tax)
     — whether it's a gain (bought below par, the common case) or a loss
     (bought above par; gilts get no CGT loss relief either, since the
     whole disposal is outside the CGT regime).
   - *Coupon income* = sum of coupons received. Taxed as **savings income**
     at the holder's marginal rate — this tool does not attempt to compute
     an actual tax bill, since that depends on the Personal Savings
     Allowance and the starting rate for savings, both of which depend on
     the holder's *other* income, which this tool has no visibility into.

An invariant checked in `calc.test.js`: `total received = invested +
capital gain + coupon income`, exactly — nothing is created or destroyed,
only the cashflow's tax character differs.
